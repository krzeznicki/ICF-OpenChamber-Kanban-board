# Changelog

## 0.5.2

- **Floating bulk action panel** for marked cards: state/type, column moves, GitHub labels, parent/unparent, shared blockers, Start Task, archive/restore, copy and delete. Compact centered icon groups, eligibility previews, disabled unavailable actions and explicit confirmation.
- Partial failures stay selected for retry, including metadata migration after task IDs change. Uncertain starts and failed first-message delivery do not dispatch duplicate agents on retry.
- Marking cards preserves page scrolling; action forms retain focus during refreshes and fit narrow screens.

## 0.5.1

- **Marked cards**: Cmd+click (Ctrl+click elsewhere) marks a card, Shift+click marks a range across columns, as in a file list. Dragging a marked card moves every marked card to the column (a count on the dragged card); Mod+Shift+←/→ moves them too. Refusals are said once, close and start questions come one at a time, starts respect the agent limit. A plain click, a click on the background or Escape clears the marks (`marks.ts`, `GLOSSARY.md`).

## 0.5.0

- **Several sources per project** (local `.scratch/` files and GitHub Issues at once), one of them the **Primary source** (ADR 0001, `GLOSSARY.md`). `docs/agents/issue-tracker.md` keeps describing the primary source in Matt Pocock's format; an optional `## Additional sources` section lists the others with instructions for agents. Without it a project has one source, as before.
  - A combined tracker (`core/sources.ts`) lists every source (one failing source does not hide the others) and routes each operation to the source that owns the id. Every task carries `source`. Each source declares its capabilities and availability (`ok`, `needs-login`, `unavailable`).
  - New tasks go to the primary source unless one is named; a sub-task always goes to its parent's source. A parent or blocker in another source is refused (INVALID).
  - CLI: `create --source`, `list`/`next` read every source (the source is named on each line when there are several, always in `--json`) and `--source` narrows them; `init --add/--remove/--primary`; `publish <id> [--to github]`; `delete <id> [--with-children]`.
  - Board: a source switcher (`All | Local | GitHub`) next to the project switcher when a project has several sources, kept per project, the primary source on first opening. A source badge on cards in All. The `source:` search filter with suggestions. A banner with **Try again** for a source that fails to list (its own text when it needs a login); archive marks and card order of its tasks are kept.
  - Add task has a **Source** select whenever the project has several sources, starting on the source the board shows (in All, the primary source). Parent, blockers and existing sub-tasks come only from the chosen source.
  - Settings → **Sources**: add, remove (deletes nothing) and make a source primary; the file Settings writes is the one `init --add` writes. Replacing a hand-edited template asks first; hand-written notes and later sections are kept.
  - **Publish to GitHub** on a local task (in the task modal, on the right of the Move to row): creates the issue (sub-tasks as sub-issues, state label carried over), then closes the local files with a link to it. On a partial failure it names what was created and leaves the local files open.
  - The task modal links a GitHub task to its issue (**Open on GitHub ↗**) right under its title, instead of inside the collapsed Settings section.
  - A session started from a card gets the tracker instructions of that task's source. The `icf-kanban-*` skills describe `--source` and the parent's-source rule.
- A move (a drop, Move to, the State select, closing) shows at once: the card sits in its new column while the write and the reload from the source (several `gh` calls for GitHub) run in the background (`optimistic.ts`). A reload landing meanwhile does not snap it back; a failed write is a toast and the card goes back.

One failed delete does not stop the rest; each failure gets its own toast. Session links, queued starts, start options and card places of deleted tasks go with them.

## 0.3.6

- Fixed: a queued card the service started in a new worktree without a model or an agent set never started and ended as **Couldn't start: … OpenChamber could not reach the session. (failed 3 times …)**. OpenCode answers an empty agent list on the first call for a folder it has not loaded, which every new worktree is; OpenChamber then refuses the start with 503. Not for done or `wontfix` tasks, boards without types, or tasks created with **No type** in Add task (kept as `noType:<projectId>:<taskId>` in the panel's storage, following a new id, dropped on delete). **Suggest type and state for new tasks** switches it off.
- **Edit** in the task modal's header turns the Task section into a title and description (markdown) form; `Tracker.edit`, the service's `/tasks/edit` (`{ id, title?, body? }` -> `{ task }`) and `task-board edit <id> [--title <t>] [--body-file <f>|-]`. The id stays (locally the file is not renamed); locally the heading's number, the `Type` / `Status` / `Blocked by` lines and the `## Comments` / `## Answer` sections are kept. Save sends only the changed fields and refuses, with the draft kept in the form, when one of them was changed meanwhile (e.g. by an agent) or the task is busy.

Deleted tasks and ids the tracker no longer lists are pruned. In its own column only a card's middle makes the dragged card its sub-task.

## 0.3.1

- The task modal links existing tasks both ways: a **Parent** picker in the State / Type row moves the task under another open parent (shown read-only when the task has a parent but nowhere else to go), and **Link existing task** in Sub-tasks (next to Add sub-task) makes a chosen task a sub-task of this one. Both offer only what the tracker accepts (`link.ts` `linkChoices`: locally parents are features and a feature with tickets cannot become a sub-task; never the task itself, its current parent or, on GitHub, one of its descendants), search when the list is long, and show the service's error in the modal. A local link gives the task a new id; the open modal follows it and the board reloads.
- Dropping a card onto another card makes it that card's sub-task (`setParent`). While dragging, a card that accepts it (`link.ts`: locally a feature, not the task itself or its current parent, and a feature with tickets cannot move; on GitHub never one of its own descendants) is highlighted with a dashed outline instead of its column; over any other card the drop is the column move as before. A confirm names both tasks (locally: the task gets a new id and its blockers are dropped); then the board reloads, and a failure shows as a toast. An open task modal showing the dragged task follows it to its new id.
- An existing task can be linked under an existing parent: `Tracker.setParent(id, parentId)`, the service's `/tasks/parent` (`{ id, parentId }` -> `{ task }`), the panel API's `setParent` and `task-board parent <id> <parentId>` (with `--json`). GitHub sets the native parent with `gh issue edit --parent` (gh 2.94+, the existing minimum), replacing an old one; the number stays. Locally the file moves into the parent's feature as its next ticket (heading renumbered, its `Blocked by` dropped, and its old feature's tickets that listed it lose that blocker), or a feature with no tickets becomes a ticket and its folder is removed; a feature with tickets, a feature whose folder holds files besides `spec.md` (named in the error, so no empty feature is left behind), a ticket as the parent, the task itself and its current parent are refused (INVALID) before anything is written. GitHub also refuses one of the task's own descendants as its parent (INVALID), walking up the would-be parent's chain before `gh issue edit`. The returned task carries the new id; the service re-keys the task's session links (`links.json`) and queue entry to it, so the card keeps its session; once the move is done a failing re-key is logged and the answer is still the moved task. Every link from the panel (Parent picker, Link existing task, a card dropped onto a card, Add task's existing sub-tasks) moves the card's start options (`card:<projectId>:<taskId>`) to the new id and deletes the old key.
- **Add task** offers **Existing sub-tasks**: open tasks to link under the new task once it is created (with `setParent`), where it may have sub-tasks (local: no parent, a new feature, taking open tickets and features without tickets; GitHub: any open issue except the chosen parent and its ancestors). A failing link is reported with the sub-tasks that were not created; the new task stays. Picks are checked again at submit, so one that is no longer offered (done meanwhile, gone) is skipped. On GitHub picked existing sub-tasks make the new task a parent for its start preset, like typed ones.
- `npm run build:test` builds a local test extension, **Kanban TEST** (id `icf-kanban-test`), from the checked-out branch into `~/openchamber-extensions/icf-kanban-test` (or `--out`/`KANBAN_TEST_OUT`), to install once next to production and reload on every rebuild. It keeps its data in `~/.icf-kanban-test/`, makes `icf-test/<slug>` worktree branches, ships its skills as `kanban-test-*`, tells agents it is the TEST build and shows a **TEST** badge. The variant is baked in at build time (`__KANBAN_VARIANT__`); the committed production bundles are built as `prod` and behave as before.

## 0.3.0

- The task modal shows **State**, **Type** and **Move to** in a compact row right under the header, above Summary and Task, instead of inside the collapsed Settings section. Settings keeps Open on GitHub and the card's start options (still collapsed by default) and hides when it would be empty.
- **Agent** and **Thinking** (the model's thinking level, OpenCode's `variant`) are picked from lists next to **Model** wherever start options are set: the card, Add task, the start form, Settings → Global and This project. The service's `/models/list` now asks OpenCode's server (`opencode api GET /api/model`, falling back to `opencode models`) and answers `{ models: [{ id, name, variants }] }`, so the model picker shows names; the new `/agents/list` (`GET /api/agent`) lists the session agents (primary, not hidden). Both are cached 10 minutes per project and answer a failure as `{ …: [], error }`. The pickers' default reads **Default — OpenChamber's current selection** when nothing is inherited, and a muted line under the start options explains that a set model, thinking level or agent starts the session from the extension (path B, its own worktree). A thinking level counts like a model or agent for the path choice, is passed to `sessions.start` and is kept in queued entries; it is dropped when no model is in force, and a layer or card that sets a model owns the level (a level is never inherited onto another model). Going back to the default model checks the level against the inherited model, and a card's level over an inherited model is checked again at start (dropped, with a notice, when that model is known not to offer it). Stored settings and cards without a thinking level read as none; queue entries from 0.2 still start.
- **Preset sets.** Presets now come in named sets: **Matt Pocock's skills** (0.2's skills texts), **Superpowers** (new: Plan → `brainstorming` then `writing-plans`, published to the tracker as a feature with tickets; Prototype → `brainstorming` for the question, throwaway code on a `prototype/<name>` branch; Implement and Implement without questions → `test-driven-development`, `verification-before-completion`, `requesting-code-review`; Break down and orchestrate → `writing-plans` when there are no sub-tasks, then `subagent-driven-development`; Diagnose → `systematic-debugging`, then a TDD fix; Triage → the plain text) and **Plain** (0.2's plain texts). Every skills text keeps the 0.2 rules: tracker writes through the `task-board` CLI with `--dir`, quoted placeholders, never a setup skill; the Superpowers texts also skip `using-git-worktrees` (the board made the worktree) and `finishing-a-development-branch` (merging is the user's call). Preset ids are the same in every set. **Settings → Global / This project → Preset set** picks the set (default: Matt's if all its skills are found, else Superpowers if found, else Plain); a set with missing skills can still be chosen, with a warning. **Settings → Presets** edits any set, adds your own presets to it, and adds (a copy or empty), renames and deletes your own sets; a copy keeps each preset's skills, so its sessions get the SKILL.md paths and the set's status line and picker check those skills. This replaces the 0.2 "Use Matt Pocock's skills when installed" switch (off reads as the Plain set) and the per-preset fallback to plain text when a skill was missing. Stored under `presetSets`; the 0.2 `presets` key is migrated once (its edits and own presets go to every built-in set, so the set chosen by detection runs your texts and has your presets; no set is pinned) and deleted. A deleted set chosen in This project falls back to the global choice, a deleted global one to the default.
- A bug now defaults to **Diagnose** in every set that has it (all built-in sets), else Implement; a card whose preset the project's set lacks starts with the set's Implement (Plain's Implement for an empty set).
- **Type and state suggested by your Small Model.** In Add task, Type and State start on **Let the model pick**: the task is created as `needs-triage` with no type, then `host.generate` (the Small Model; extensions have no access to OpenChamber's decision model) is asked once for `{type, state}` as JSON, with the title and description as delimited data. The answer is validated strictly (a board type; `needs-triage`, `needs-info`, `ready-for-agent` or `ready-for-human`; nothing else) and only the fields left to the model are written with setType / setState, after reading the task again: a field changed meanwhile, a card being moved, sub-tasks from the same form and tasks created elsewhere are left alone. Summaries and suggestions now share one limit of two model requests at a time (`src/panel/limiter.ts`). A missing model, a missing permission or an unusable answer keeps the defaults with one quiet notice per panel session; a late answer (panel closed meanwhile) is dropped. **Settings → Global → Suggest type and state for new tasks** (on by default, global only) switches it off.
- `/skills/detect` also reports the Superpowers skills and looks in OpenCode's plugin cache (`~/.cache/opencode/npm/*/*/node_modules/superpowers/skills`, read only) after the skill folders.
- Summaries and the type/state suggestions share one "Small Model available" flag: whichever finds the model missing or not granted gives one notice for both, automatic summaries stop, and Add task stops offering **Let the model pick**; a model answering again (Summarise) turns both back on.

## 0.1.0 (unreleased)

First version.

- Kanban board (rail panel and full-screen page) over local `.scratch/` files or GitHub Issues, in Matt Pocock's skill format, with a setup wizard for new projects.
- Columns Backlog, Ready, In Progress, Review, Done; In Progress and Review come from linked sessions and are never written to the repository.
- Drag to In Progress starts an agent session: path A through OpenChamber, or path B through the service (model or agent set on the card, or a queued start), which makes its own git worktree under `<repo>-worktrees/` when the location is a new worktree.
- Parents start one orchestrator session; sub-tasks show progress and "led by orchestrator".
- Presets (five built-in, editable, plus your own) and settings in three layers: global, project, card.
- Start queue with a per-project limit, kept in `~/.icf-kanban/queue.json` and drained after session events while the board is closed.
- Personal card summaries written by your model, in your language (default Polish).
- Agent skills `icf-kanban-create`, `icf-kanban-status`, `icf-kanban-next`, `icf-kanban-start`, the `task-board` CLI, and an instructions paragraph for every session.

Fixed before release (final review):

- Agents in a worktree reach the tracker: the first message, the instructions and the skills always pass `--dir <project root>` to the CLI.
- Claim wording: sub-tasks are created `ready-for-agent`, claim needs `ready-for-agent`, a ticket started from the board is not claimed, and `icf-kanban-start` checks `claimed` before claiming.
- A failed path B start removes the worktree and `icf/*` branch it created; a queued card stops being retried after three failed starts; a start whose link could not be saved counts as started (no duplicate session).
- GitHub setup needs a github.com remote (the wizard disables GitHub without one); remote URLs are shown without credentials.
- Dragging a card with a session to Backlog or Ready detaches it from that session instead of snapping back.
- `THIRD_PARTY_LICENSES` with `@openchamber/sdk`'s MIT licence.
