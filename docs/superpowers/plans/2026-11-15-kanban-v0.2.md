# Kanban Board 0.2 — feedback round 1

> For agentic workers: executed with superpowers:subagent-driven-development. Spec: docs/superpowers/specs/2026-11-15-task-board-design.md (still binding where not changed below). Kamil's feedback after installing 0.1.0 is the source of every task.

**Goal:** Make the board read and edit better after Kamil's first hands-on check: new name and icon, task and add-task as modals with everything settable, markdown task body, model picker, sub-tasks from the UI, Matt Pocock's skills in presets, archive Done.

## Global Constraints

- Extension id stays `icf-kanban` (a new id would lose every user's storage). Display name becomes `Kanban Board`.
- All earlier global constraints hold: sandboxed panel (no window.prompt/alert/confirm, no network, no absolute paths), Matt's repo format unchanged, In Progress / Review never written to the repo, all git/gh/opencode calls through the injectable `Exec`, every task ends with `npm run check` green, bundles rebuilt and committed, check-guest "Package is ready".
- UI text in English. Controls from the SDK UI kit where one exists.
- Untrusted text (task titles, bodies, model output) never becomes executable markup.

### Task 1: Name, icon, close button, drop the Close action

Kamil: "rename the panel to Kanban Board, pick a better icon"; "the Done button top-right of an open task is confusing, make it an X"; "the Close button on the task card moves it to Done, confusing and unneeded".

- `package.json`: `contributes.panel.name` and the page title → `Kanban Board` (page title may stay `Board` if the menu prefixes the extension name — check API.md and choose the reading that shows "Kanban Board" once). Icon: ship `assets/kanban.svg` (three columns with cards, `currentColor`, 24×24 viewBox) and point `panel.icon` at it.
- Detail view: replace the top-right "Done" text button with an icon-only close button (×, `aria-label="Close"`), Escape still closes.
- Remove the detail view's "Close" / "Close with sub-tasks" action buttons. Moving to Done stays possible by drag and by Move to → Done (which still asks about open sub-tasks).
- README: name and screenshots list updated.
- Tests: none new beyond what exists unless logic changes; check-guest must accept the SVG icon.

### Task 2: Model picker from the available models

Kamil: "the model should be picked from the list of available models, not typed".

- Service: `POST /models/list` → `{ models: string[] }` (`provider/model`), from `opencode models` run through Exec (add `"opencode"` to `service.permissions.exec`). Cache in memory for 10 minutes; on failure answer `{ models: [], error }` (never 500). Tests with a fake exec (parse, cache, failure).
- Panel: a searchable model picker (text filter + list, keyboard friendly; SDK `mountSearchField` + `mountList`, or `mountSelect` if it supports filtering) with a first option "Default (current selection)" meaning `null`. Used everywhere a model is chosen: card start options, global/project defaults in Settings, and the add-task modal (Task 4). A stored model missing from the list still shows as its own entry ("not in the list").
- The list loads once per panel session, lazily when a picker first opens.

### Task 3: The task opens as a readable modal

Kamil: "when I open a task I want to read it first: summary and details first, settings below, collapsible sections, settings collapsed by default; the full task as formatted markdown; maybe open tasks as a modal, more room"; "a card in Review or Done doesn't open the task but jumps to the session, and when the session was archived it opens another active session from another project. The card should always open the task, with a 'go to session' button at the top when it has one".

- Clicking a card always opens the task modal (centered overlay, large: up to ~900px wide, scrolls inside; in the narrow rail panel it fills the panel). No click opens a session directly.
- Order: header (title, id, type/state badges, × close; "Open session" button when the task has a live or finished, non-archived session; "Session archived" muted text when its only session is archived — never call openSession for an archived or unknown id), Summary section, Task section (body rendered as formatted markdown, expanded), Sub-tasks section (parents), Settings section (state, type, Move to, start options) collapsed by default. Sections are collapsible; remember open/closed per section in device storage if cheap, else per panel session.
- Markdown: use `markdown-it` with `html: false` (raw HTML in a body is shown as text), links open through `host.openUrl` (http/https only), task-list checkboxes render read-only. Build DOM from tokens or set innerHTML of markdown-it's output — either way raw HTML must never pass through; add a test that `<img src=x onerror=…>` and `javascript:` links come out inert.
- Diagnose the archived-session jump first (superpowers:systematic-debugging): find why openSession landed on another project's session (likely a links.json fallback or snapshot entry for an archived id). Fix the cause, add a test at the level where it lives.

### Task 4: Add-task modal with every per-task option, and sub-tasks from the UI

Kamil: "adding an issue should be a modal with all options settable per task"; "sub-tasks should be addable both when adding the main task and after opening a task, not only by picking a parent on a new task".

- "Add task" opens a modal: title (required), type, parent (None or an open parent), state (default needs-triage), blocked by (multi-select of open tickets in the same feature/repo), description (markdown textarea), start options (preset, model via Task 2's picker, agent, location, summary language), and a "Sub-tasks" list (add rows of titles; each created under the new task after it is created).
- Local tracker: a task with no parent becomes a feature (spec.md), so its sub-tasks are tickets under it. A ticket with a parent can't take sub-tasks locally — hide the Sub-tasks list when a parent is chosen on a local project, with a one-line hint.
- Task modal: "Add sub-task" inline (title + optional type) in the Sub-tasks section, for parents; locally only for features; on GitHub for any open issue (it becomes a parent).
- Errors from the service show inside the modal; partial failure (parent created, a sub-task failed) says which sub-tasks were not created.
- Card start options saved with the existing `card:<projectId>:<taskId>` key once the task id is known.

### Task 5: Presets on Matt Pocock's skills when installed

Kamil: "if Matt's skills are installed I want presets to use them: grill-with-docs for planning, prototype for prototyping, the implementation skills used together; use ask-matt to lay out a flow".

Flow (from ask-matt, main flow idea → ship):
- **Plan** → `/grill-with-docs` to sharpen the task, then, for a multi-session build, `/to-spec` and `/to-tickets` (sub-tasks through the board CLI's tracker, which is the same format).
- **Prototype** → `/prototype` answering the task's design question on a `prototype/<name>` branch; report the answer back on the task.
- **Implement** → `/implement` (it drives `/tdd` and closes with `/code-review`).
- **Implement without questions** → `/implement`, deciding unclear points yourself and listing assumptions.
- **Break down and orchestrate** (parents) → `/to-tickets` if the feature has no sub-tasks, then `/implement-spec` over the sub-tasks.
- New built-in **Diagnose** → `/diagnosing-bugs`, then `/implement` for the fix. Default preset for type `bug` becomes `diagnose` when Matt's skills are found.
- New built-in **Triage** → `/triage` for Backlog items that arrived raw.

Mechanics:
- Service: `POST /skills/detect {directory}` → `{ found: string[] }`: which of the names above exist as `<dir>/<name>/SKILL.md` in `~/.config/opencode/skills`, `~/.claude/skills`, `~/.agents/skills`, `<project>/.opencode/skills`, `<project>/.claude/skills`. Read-only, never `~/.config/openchamber`. Tests with a temp HOME.
- Each built-in preset gets `mattText` next to `text`. The prompt uses `mattText` when the setting "Use Matt Pocock's skills when installed" (global, default on) is on and every skill that preset names is found; otherwise `text`. A user-edited built-in keeps the user's text. Settings shows which skills were found.
- Tests: resolve which text is used; detection.

### Task 6: Archive Done

Kamil: "we need to clear the board: an 'archive done' button; archived tasks no longer show in Done".

- Done column header: "Archive done" button (with in-panel confirm showing the count). Archived task ids per project in storage `archived:<projectId>` (`{ id, archivedAt }[]`); ids no longer listed by the tracker are pruned on load.
- Archived tasks are hidden from the board. A "Show archived (N)" toggle in the Done header shows them again muted, with "Unarchive" in their task modal.
- A task that leaves Done (reopened) is unarchived automatically.
- Nothing changes in the repo or on GitHub (done tasks are already resolved / closed).
- Tests: pure archive helpers (hide, prune, auto-unarchive).
